# Lifecycle and gates

Version: 1.0.

1. Establish task ID, requested outcome, exact repository/work areas and current authorization. Read applicable policies/knowledge; record HEAD/status plus relevant untracked baseline. Resolve dirty work before edits unless user explicitly scoped isolated additions.
2. Assign risk and measurable acceptance criteria. Record assumptions and unknowns; research only authorized sources. Stop affected unsafe work while independent safe work continues.
3. For new architecture/material scope: interview one principal question at a time where needed; audit decisions; read-only discovery; evidence-based proposal; explicit architecture/scope approval before implementation. Ordinary approved local implementation does not reopen settled questions.
4. Partition acceptance units and file/resource ownership. Dispatch specialists with bounded handoffs. Revalidate game/session/permissions before effects.
5. Implement complete bounded behavior, relevant tests, docs and stable contracts. Record actual evidence, limits and resource budgets. Checkpoint task-owned changes only.
6. For L2/L3 or protected controls, independent audit actual baseline/diff/tests/contracts. Fix blockers and re-audit changed scope. Human explicitly accepts verdict and exact audited content.
7. Consolidate approved unpublished checkpoints, confirm identical tree/content and rebind audit metadata. Never treat rewording as authorization to change behavior.
8. Report and preserve recoverable state. Release/push/deploy permissions are separate.

Primary outcome: COMPLETED only if required criteria and mandatory gates are verified; otherwise PARTIAL, BLOCKED, REJECTED or CANCELLED. Record implementation, verification and human acceptance separately. An artifact can be implementation-ready while human acceptance remains pending; report task PARTIAL in that case. Checks use PASS/FAIL/BLOCKED/NOT_RUN. No unexecuted test is PASS.

Session resumption rechecks status, permissions and evidence freshness. Historic records do not override current files. Noninteractive missing decisions stop safely. Bounded retries require cause/justification; don't repeat a side-effectful operation with ambiguous outcome before observing state.
